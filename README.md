# AI Programming Mentor Framework (APMF)

> ⚠️ **Project Status**
>
> This framework is currently under active development.
> The architecture is considered stable enough to begin practical use, but individual documents and teaching methodology are expected to evolve based on real educational experience.

> **An open framework for learning programming with AI as a structured mentor.**



## Overview

AI Programming Mentor Framework (APMF) is an educational framework designed to transform a general-purpose Large Language Model (LLM) into a structured programming mentor.

Unlike traditional prompts or static tutorials, APMF separates educational methodology from the AI model itself. The framework defines **how an AI teacher should teach**, **how a student should learn**, and **how learning progress should be evaluated**.

The long-term objective is not simply to teach a programming language, but to develop the knowledge, reasoning, and engineering mindset required for independent software development.

Although the initial implementation focuses on Python, the framework is language-agnostic and can later be adapted to other programming languages.

---

# Philosophy

APMF is built around several core principles:

* Teach programming concepts before language syntax.
* Develop problem-solving skills before memorization.
* Encourage independent thinking instead of passive code generation.
* Integrate learning with real software projects whenever possible.
* Continuously reduce the student's dependency on AI assistance.
* Treat AI as a mentor rather than a replacement for the learner.

# Components

## AI Programming Mentor Specification

Defines the educational philosophy, teaching methodology, behavioral rules, learning modes, competency model, and system architecture.

This document acts as the "constitution" of the framework.

---

## Teacher Prompt

Contains the system prompt that adapts an LLM into an APMF-compliant programming mentor.

The prompt is intentionally lightweight.

Most educational logic belongs to the Specification rather than the prompt itself.

---

## Student Profile

Describes the learner's current experience, objectives, preferred learning style, long-term goals, and ongoing software projects.

This document allows the AI teacher to personalize the educational process.

---

## Curriculum Roadmap

Defines the complete learning path from beginner to independent software developer.

Each stage contains learning objectives, required competencies, assessment criteria, and practical milestones.

---

## Learning Modules

Each module teaches a specific competency.

Modules include:

* conceptual explanations;
* practical exercises;
* checkpoints;
* project integration tasks;
* homework;
* completion criteria.

---

## Competency Matrix

Tracks practical skills rather than completed lessons.

Progress is measured by demonstrated abilities, not by time spent studying.

---

## Checkpoint Reports

At the end of every module, the AI teacher generates a structured progress report.

These reports summarize:

* completed topics;
* strengths;
* recurring mistakes;
* competency levels;
* recommendations for future study.

Checkpoint reports are intended for review by the educational architect (or another supervising AI), who evaluates overall progress and updates the learning plan when necessary.

---

# Roles

The framework distinguishes between three different roles.

## Educational Architect

Designs and continuously improves the curriculum, educational methodology, competency model, and assessment system.

The architect evaluates long-term progress and updates the framework when necessary.

---

## AI Teacher

Conducts daily lessons.

Responsibilities include:

* explaining concepts;
* assigning exercises;
* reviewing solutions;
* answering questions;
* evaluating competency growth.

---

## Student

The student actively participates in the learning process by solving problems, asking questions, completing projects, and gradually assuming greater responsibility for software development.

---

# Language Policy

The framework documentation is written in English to maximize portability, maintainability, and compatibility across AI models.

However, the language used during lessons is independent of the documentation language.

The AI teacher should communicate with the student in the student's preferred language unless explicitly instructed otherwise.
