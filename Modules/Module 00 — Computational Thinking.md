**Framework:** AI Programming Mentor Framework (APMF)

---

# 1. Module Purpose

This module introduces the fundamental mental models required for programming.

The objective is not to teach programming syntax.

The objective is to develop the ability to think like a programmer.

Before writing code, a programmer must learn how to:

* understand problems;
* define goals;
* analyze situations;
* create logical solutions;
* communicate instructions precisely.

---

# 2. Learning Objectives

After completing this module, the student should understand:

* what programming actually is;
* how computers execute instructions;
* the difference between a problem and a solution;
* what algorithms are;
* how complex tasks are decomposed;
* why precision matters in programming.

---

# 3. Core Concepts

---

# 3.1 What Is Programming?

Programming is the process of creating precise instructions that allow a computer to perform a task.

A computer does not understand human intentions.

It only executes instructions according to defined rules.

The programmer's responsibility is to transform:

```
Human goal
    ↓
Logical solution
    ↓
Computer instructions
```

---

# 3.2 Computers and Instructions

A computer is extremely powerful at following instructions.

However, it has no ability to:

* guess intentions;
* understand ambiguity;
* infer missing information.

Humans often communicate using context.

Computers require explicit instructions.

Example:

Human instruction:

> "Make tea."

A person understands:

* boil water;
* prepare cup;
* add tea;
* wait;
* drink.

A computer needs every step defined.

---

# 3.3 Problem Decomposition

Large problems are usually too complex to solve directly.

Programming requires breaking problems into smaller manageable parts.

Example:

Goal:

> Create a personal expense tracker.

Possible decomposition:

```
Expense tracker

├── Store expenses
├── Add new expense
├── Calculate totals
├── Display information
└── Save data
```

Each smaller part can then be solved independently.

---

# 3.4 Algorithms

An algorithm is a sequence of steps designed to solve a problem.

Algorithms exist independently from programming languages.

Example:

Problem:

> Find the largest number in a list.

Algorithm:

1. Take the first number as the current maximum.
2. Compare it with the next number.
3. Replace the maximum if the next number is larger.
4. Repeat until the list ends.

Only after creating the algorithm do we translate it into code.

---

# 3.5 Input, Processing, Output

Most programs can be understood as a transformation:

```
Input

↓

Processing

↓

Output
```

Example:

Weather application:

Input:

* location

Processing:

* retrieve weather data
* analyze information

Output:

* weather forecast

Understanding this model helps analyze almost any program.

# 4. Practical Exercises

---

# Exercise 1 — Human Algorithm

Choose a simple everyday task.

Examples:

* making coffee;
* preparing a meal;
* starting a computer;
* organizing files.

Write instructions precise enough that another person could follow them without assumptions.

Goal:

Understand why computers require precise instructions.

---

# Exercise 2 — Problem Decomposition

Choose a simple software idea.

Examples:

* calculator;
* notes application;
* task manager;
* image organizer.

Break it into smaller components.

Do not write code.

Only identify:

* major parts;
* responsibilities;
* relationships.

---

# Exercise 3 — Algorithm Design

Create an algorithm for a simple problem.

Examples:

* finding a specific file;
* sorting a collection of items;
* deciding whether a user can access a feature.

Describe the solution using plain language.

---

# 5. Reflection Questions

The student should be able to answer:

1. What is the difference between a goal and an algorithm?

2. Why can a computer not simply "understand what we mean"?

3. Why is breaking a large problem into smaller parts useful?

4. Why is code not the first step of programming?

5. Can the same algorithm be implemented in different programming languages?

---

# 6. Integration With Real Projects

The student should analyze an existing project and identify:

* What problem does the project solve?
* What are the major components?
* What are the inputs?
* What are the outputs?
* What tasks inside the project can be decomposed further?

The goal is to begin viewing software as a system of interacting parts.

---

# 7. Completion Criteria

The module is completed when the student can:

* explain programming as problem solving rather than typing code;
* describe algorithms independently from programming languages;
* decompose simple problems into smaller components;
* create logical step-by-step solutions;
* explain the input-processing-output model.

---

# 8. Mentor Notes

The mentor should not rush this module.

The concepts introduced here are foundational for all future programming knowledge.

A student who understands these principles will learn syntax faster.

A student who skips these principles may memorize syntax without developing programming ability.
