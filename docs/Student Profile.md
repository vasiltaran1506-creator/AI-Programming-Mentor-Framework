# Student Profile

**Framework:** AI Programming Mentor Framework (APMF)

**Version:** 0.1 Alpha

**Status:** Active

---

# 1. Student Overview

The student is a motivated beginner programmer who is starting from a near-zero programming background.

The student has experience working with AI-assisted software development and has already participated in creating real software projects with significant AI assistance.

The primary educational goal is to transform existing AI-assisted development experience into genuine programming knowledge, understanding, and independent engineering ability.

---

# 2. Current Skill Level

## Programming Knowledge

Current level:

**Beginner / Pre-Junior**

The student:

* does not have formal programming education;
* does not yet have a strong understanding of programming fundamentals;
* may recognize programming concepts from existing AI-generated code;
* requires explanations starting from fundamental principles.

The mentor must not assume knowledge of:

* variables;
* control flow;
* functions;
* data structures;
* algorithms;
* object-oriented programming;
* software architecture;
* debugging methodology.

---

# 3. Previous Experience

The student has practical experience with AI-assisted development.

Existing experience includes:

* creating software projects with AI-generated code;
* managing project structures;
* discussing software architecture;
* working with development tools;
* understanding project goals and requirements.

This experience should be treated as an advantage.

The student is not starting from zero in terms of software development awareness, but is starting from zero in terms of formal programming knowledge.

---

# 4. Primary Learning Objectives

The student's main objective is:

> Become capable of independently designing, writing, understanding, debugging, and maintaining software.

The student should progress from:

```
AI writes code
        ↓
Student understands code
        ↓
Student modifies code
        ↓
Student writes parts independently
        ↓
Student designs solutions independently
        ↓
AI becomes a development partner
```

---

# 5. Long-Term Goals

The student aims to:

* reach Junior Developer competency level;
* understand programming fundamentals deeply;
* write code independently;
* understand existing codebases;
* make architectural decisions;
* effectively use AI as a professional development tool;
* continue learning new technologies independently.

---

# 6. Preferred Learning Style

The student prefers:

* systematic explanations;
* understanding the reasons behind concepts;
* learning through practical application;
* connecting theory with real projects;
* structured learning paths;
* clear progression milestones.

The student benefits from explanations that answer:

1. What is this?
2. Why does it exist?
3. How does it work?
4. When should it be used?
5. How is it applied in a real project?

---

# 7. Learning Preferences

The mentor should prioritize:

## Conceptual Understanding

The student prefers understanding principles rather than memorizing syntax.

Example:

Prefer:

"Functions allow us to create reusable units of logic with defined inputs and outputs."

Before:

"Here is the syntax for defining a function."

---

## Practical Context

Whenever possible, explain concepts through realistic programming tasks.

---

## Visible Progress

The student benefits from understanding:

* what has already been learned;
* what is currently being developed;
* what remains ahead.

---

# 8. Motivation

The student is motivated by:

* creating useful software;
* solving real problems;
* improving existing projects;
* seeing practical results.

Purely theoretical learning without application may reduce engagement.

---

# 9. Current Project Context

The student has an ongoing software project:

**Dataset Composer**

This project should gradually become a practical learning environment.

The mentor should use it when appropriate to demonstrate:

* programming concepts;
* software architecture;
* code organization;
* debugging;
* engineering decisions.

The project should not replace fundamental learning.

Real project work and foundational education should progress together.

---

# 10. AI Usage Philosophy

The student intentionally used AI-generated code to accelerate project creation before having sufficient programming knowledge.

This is considered a starting point, not a failure.

The educational objective is not to avoid AI.

The objective is to transition from:

"AI creates software for me"

to:

"I understand software development and use AI as a powerful engineering assistant."

---

# 11. Expected Mentor Approach

The mentor should:

* avoid assuming incompetence because the student is a beginner;
* avoid assuming competence because the student has existing projects;
* explain fundamentals patiently;
* gradually increase complexity;
* encourage independent reasoning;
* provide appropriate challenge.

---

# 12. Success Criteria

The student will be considered successful when they can:

* independently understand unfamiliar code;
* decompose problems into smaller tasks;
* design simple solutions;
* write and debug programs;
* explain their own code;
* make reasonable engineering decisions;
* use AI effectively without being dependent on it.

---

# 13. Mentor Warning

The student has a tendency toward solving complex practical problems quickly with AI assistance.

This is a strength but also a potential learning risk.

The mentor should help maintain balance:

* do not unnecessarily slow down practical development;
* do not allow AI to permanently replace understanding;
* use real projects as motivation while ensuring fundamental skills are developed.
