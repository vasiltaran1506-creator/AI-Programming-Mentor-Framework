# Competency Matrix

**Framework:** AI Programming Mentor Framework (APMF)

**Version:** 0.1 Alpha

**Status:** Active

---

# 1. Purpose

This document defines the competency model used to evaluate student progress within the AI Programming Mentor Framework.

The purpose of this matrix is to measure practical ability rather than theoretical exposure.

A competency is considered developed only when the student can demonstrate the ability to apply knowledge independently.

---

# 2. Competency Philosophy

APMF evaluates:

* what the student can do;
* how independently the student can do it;
* how well the student understands their decisions.

The goal is not memorization.

The goal is engineering capability.

---

# 3. Competency Levels

Each competency is evaluated using five levels.

---

# Level 0 — Unknown

The student:

* has not encountered the concept;
* cannot explain it;
* cannot apply it.

---

# Level 1 — Familiar

The student:

* recognizes the concept;
* understands basic terminology;
* can follow explanations.

The student still requires significant guidance.

---

# Level 2 — Guided Application

The student:

* can apply the concept with examples;
* can complete tasks with mentor assistance;
* understands the general purpose.

---

# Level 3 — Independent Application

The student:

* can apply the concept independently;
* can solve common problems;
* can explain their decisions.

This level represents practical competency.

---

# Level 4 — Advanced Understanding

The student:

* can optimize solutions;
* understands trade-offs;
* can teach the concept to others;
* can apply knowledge in unfamiliar situations.

# 5. Junior Developer Readiness Criteria

The student can be considered Junior-level when they demonstrate:

* Level 3 competency in fundamental programming areas;
* ability to independently build small-to-medium applications;
* ability to understand existing code;
* ability to debug problems;
* ability to use professional development tools;
* ability to collaborate effectively with AI and humans.

---

# 6. Assessment Rules

The mentor should not increase complexity if fundamental competencies remain unstable.

A student may temporarily work on advanced projects while still developing lower-level skills.

However, missing foundational competencies should eventually be addressed.

---

# 7. Progress Tracking

Competency progress should be recorded through:

* checkpoint reports;
* practical tasks;
* project milestones;
* code reviews;
* demonstrations of independent work.
