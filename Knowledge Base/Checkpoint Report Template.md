# Checkpoint Report

**Framework:** AI Programming Mentor Framework (APMF)

**Version:** 0.1 Alpha

**Status:** Active

---

# 1. Purpose

This document defines the format used by the AI Teacher to evaluate student progress after completing a learning stage, module, or significant milestone.

The purpose of a checkpoint report is not to grade the student.

The purpose is to create an accurate representation of:

* current abilities;
* acquired competencies;
* remaining difficulties;
* recommended next steps.

---

# 2. Report Principles

Checkpoint reports shall follow these principles:

## Accuracy Over Encouragement

The report must represent the student's actual ability.

Positive feedback is valuable, but it must not hide unresolved problems.

---

## Evidence-Based Evaluation

Every assessment should be based on observable evidence.

Examples:

* completed exercises;
* project contributions;
* explanations provided by the student;
* code written by the student;
* debugging attempts;
* architectural decisions.

---

## Competency-Based Assessment

Reports evaluate demonstrated competencies rather than completed lessons.

---

# 3. Report Structure

Each checkpoint report should contain the following sections.

---

# 1. General Information

```text
Student:
Date:
Checkpoint:
Module / Stage:
Teacher:
```

---

# 2. Summary

A short overview of the current learning state.

Include:

* overall progress;
* major achievements;
* current challenges;
* general recommendation.

---

# 3. Completed Learning Areas

List the concepts and skills covered during the checkpoint.

Example:

```text
Completed:

- Variables and data types
- Basic control flow
- Simple functions
- Algorithm decomposition
```

---

# 4. Competency Evaluation

Each relevant competency should be evaluated.

Format:

```text
Competency:

Current Level:

Evidence:

Confidence:

Notes:
```

Example:

```text
Competency:
PF-003 Functions

Current Level:
Level 2 — Guided Application

Evidence:
Student can write simple functions but still needs help designing function responsibilities.

Confidence:
High

Notes:
Continue practicing decomposition.
```

---

# 5. Strengths

Describe demonstrated strengths.

Possible categories:

* conceptual understanding;
* problem solving;
* persistence;
* creativity;
* engineering thinking;
* practical application.

---

# 6. Weaknesses and Knowledge Gaps

Identify areas requiring improvement.

The mentor should include:

* missing concepts;
* unstable understanding;
* repeated mistakes;
* incorrect assumptions.

---

# 7. Common Mistakes Pattern

Record recurring patterns.

Examples:

```text
- Attempts coding before analyzing the problem.
- Uses AI solutions without reviewing logic.
- Has difficulty naming responsibilities.
```

Identifying patterns is more valuable than listing isolated mistakes.

---

# 8. Independence Assessment

Evaluate the student's current level of independence.

Use the following scale:

## Dependent

Student requires significant guidance.

---

## Assisted

Student can solve problems with hints.

---

## Semi-Independent

Student can solve familiar problems independently.

---

## Independent

Student can solve unfamiliar problems through reasoning.

---

## Professional

Student can design solutions and evaluate trade-offs.

---

# 9. AI Usage Assessment

Evaluate how effectively the student uses AI.

Categories:

## Prompting Ability

Can the student describe technical problems clearly?

---

## Code Evaluation

Can the student understand and review AI-generated code?

---

## Decision Making

Can the student determine when AI assistance is appropriate?

---

# 10. Project Integration

Describe how newly acquired knowledge has been applied to real projects.

Include:

* implemented features;
* improved understanding;
* architectural changes;
* discovered problems.

---

# 11. Recommended Next Steps

The mentor should provide:

* next learning objectives;
* recommended exercises;
* project tasks;
* concepts requiring reinforcement.

---

# 12. Curriculum Adjustment Recommendation

The mentor should indicate whether the current roadmap should:

* continue as planned;
* slow down;
* revisit previous concepts;
* increase difficulty;
* change learning approach.

---

# 13. Final Mentor Assessment

A concise professional summary.

Example:

```text
The student has developed a stable understanding of basic programming concepts.
The next focus should be improving independent problem decomposition and writing larger programs without assistance.
```

---

# 14. Student Reflection

The student should answer:

* What concepts became clearer?
* What remains confusing?
* What was the most difficult part?
* What would you like to explore further?

---

# 15. Report Usage

Checkpoint reports should be used by:

## AI Teacher

To adapt daily learning.

## Student

To understand progress.

## Educational Architect

To evaluate and improve the learning system.
